# Security status

This application is incomplete. Do not store passwords, tokens or secure notes in ordinary notes or connection fields. An experimental Windows-only vault uses Windows Credential Manager for secret values and SQLite only for name, username and opaque reference. It has not undergone a complete security review or end-to-end desktop verification; do not rely on it for real credentials yet.

Notes, tasks, project paths, connection metadata and session summaries are stored unencrypted in a local SQLite database in the application data directory. Access is governed by the Windows account and filesystem permissions. Backups are also unencrypted and contain this data plus vault metadata; they do not include vault secrets. Keep them in a protected location. Windows credentials are tied to the Windows account and are not guaranteed to be recoverable from a database backup or on another machine. A backup is created only at a new path and will not overwrite an existing file. If creation fails, an empty or incomplete file may remain and should not be treated as a valid backup. Restore is not yet implemented.

Project scanning does not read project file contents, skips common generated folders and Windows reparse points, and has depth and directory limits. Import rechecks discovered paths. The selected editor executable is explicitly confirmed by the user and launched directly with a project path as a separate argument, without invoking a shell. Saved commands launch explicitly selected executables with argument arrays after confirmation. Some common shells are blocked, but this is not a sandbox: an approved executable can perform arbitrary actions. Arguments are stored in plaintext and must not contain secrets. Output and exit status are kept in memory only, with a combined 64 KiB limit; output may contain sensitive data. A child process that inherits output handles can delay completion reporting. Cancellation is not implemented. Web connections can open an HTTP or HTTPS URL in the default browser after explicit confirmation; SSH, RDP and AnyDesk launching are not implemented. The connection directory is unencrypted and must not contain passwords, tokens, or credential-bearing addresses. The vault supports add, metadata editing, secret replacement, explicit reveal, hide and delete. Replacement creates a new credential before switching its database reference; failed cleanup can leave an orphaned protected credential and is reported. Copy, secure-note handling and portable secret backup are not implemented. A view lock clears visible and in-progress secrets after five minutes of inactivity or when the page is hidden, but can be unlocked without reauthentication. Revealed secrets are held temporarily in frontend memory and hidden after 30 seconds; this is not a cryptographic lock. The view lock does not revoke Windows Credential Manager access or guarantee memory zeroization. A failure between writing the credential and saving metadata can leave an orphan if cleanup also fails; deletion can similarly leave metadata if the database write fails. A complete security review and end-to-end tests are still required.

Manual automations currently support only creating notes or tasks opening a registered project folder, and opening validated HTTP/HTTPS URLs. Values are stored unencrypted. They require a preview confirmation, recheck stored actions before each step, and stop on errors; already completed actions are not rolled back.

Update: Secure notes are encrypted with Windows DPAPI (user scope) using a per-note key held in Credential Manager; other secrets are stored only in Credential Manager. Search, filters and lists use metadata only. The vault view lock time and the clipboard clearing delay are configurable; clipboard clearing happens only if the clipboard still holds the copied value and cannot erase clipboard history. Notifications contain counts and generic text only. Global shortcuts and the start-with-Windows entry are user settings; an automation shortcut only opens the review dialog and never runs silently. Sensitive saved commands cannot run from automations. The optional connection test opens a TCP connection to the saved host and port only when you click it.
