# Database

The application uses `dashboard.sqlite3` in the Tauri application data directory. SQLite foreign keys are enabled for each connection. The `user_version` migration acquires an immediate write lock before reading the version, applies changes atomically, advances older databases through version 15, and rejects newer versions. Items store ordinary notes and tasks, categories, tags, optional project references, trash state, priority and due date. Projects store names, paths and last-opened timestamps; sessions store a project reference, summary, next action and creation time. Settings store the selected editor executable path. Vault metadata stores names, usernames and opaque references, never vault secrets; secrets reside in Windows Credential Manager. Automations have ordered action records and execute only after explicit review. Saved commands contain executable paths and plaintext arguments; never put secrets in arguments. Connection records contain non-secret metadata and optional project links. Task creation and completion actions are recorded from version 6 onwards; earlier history is not reconstructed. Removing a project clears its item links and deletes its sessions.

The settings page creates a consistent SQLite snapshot with `VACUUM INTO` at a new user-selected path. It does not include WebView theme/language settings. Backups are unencrypted, cannot overwrite an existing file, and do not provide a restore UI yet. Test backup files before relying on them.
